## What I Learned

بهذا اليوم حسيت إنه المشروع صار أقرب لتطبيق حقيقي، لأنه ما عدنا نركز على Widget وحدة أو Concept لحاله، بل صار أغلب الشغل عبارة عن تنظيم المشروع وربط كل الأجزاء مع بعض.

تعلمت كيف أستخدم BottomNavigationBar حتى أتنقل بين أكثر من شاشة داخل التطبيق بطريقة مرتبة، وهي من أكثر الأشياء اللي بنشوفها بأي تطبيق موبايل.

بعدها دخلنا على ThemeData، وفهمت إنه بدل ما أكرر نفس الألوان والخطوط بكل شاشة، بقدر أحددهم مرة وحدة، وكل التطبيق يستخدمهم.

كمان تعلمنا فكرة Shared Widgets، وهي إنه إذا في Widget مستخدمة بأكثر من مكان، الأفضل أعملها بملف مستقل وأعيد استخدامها بدل ما أكرر نفس الكود أكثر من مرة.

آخر جزء كان إضافة منطق شاشة الـ Todo، بحيث التطبيق يصير يتعامل مع المهام بطريقة أوضح ويكون كل جزء مسؤول عن وظيفة معينة.

## Bottom Navigation Bar

هو شريط تنقل موجود أسفل التطبيق.

كل أيقونة تمثل شاشة مختلفة داخل التطبيق، ولما يضغط المستخدم عليها ينتقل مباشرة للشاشة المطلوبة.

صار عندنا:

Home
Todo
Completed
Profile

وبالتالي صار التطبيق أسهل بالاستخدام من قبل.
## ThemeData

تعلمت إنه ThemeData مسؤول عن الشكل العام للتطبيق.

بدل ما أحدد لون كل Button أو Text بكل شاشة، بقدر أحددها مرة واحدة داخل ThemeData.

ومن ميزاته:

توحيد الألوان.
توحيد شكل التطبيق.
تقليل تكرار الكود.
سهولة تعديل التصميم لاحقاً.
## currentIndex

تعلمت إنه كل شاشة لازم تعرف إنها هي الشاشة الحالية.

مثلاً:

currentIndex: 0

يعني المستخدم موجود داخل Home.

أما إذا كانت شاشة Completed:

currentIndex: 2

فبالتالي الأيقونة الخاصة فيها تظهر محددة.
## onItemSelected

هي Function تستقبل رقم الصفحة اللي ضغط عليها المستخدم.

ومن خلال قيمة الـ index أحدد لأي شاشة لازم أنتقل.

مثلاً:

if(index == 1){
   // Todo Screen
}

وبالتالي صار التنقل يعتمد على رقم الصفحة وليس على كل زر بشكل منفصل.
## Reusable Widgets

من أهم الأفكار اللي أخذناها اليوم.

بدل ما أكرر نفس الكود داخل كل شاشة، بعمل Widget مستقلة وأستخدمها بأي مكان.

مثلاً:

Task Card

صار يُستخدم داخل أكثر من شاشة بنفس الشكل.

وهذا بخلي المشروع مرتب وأسهل للصيانة.
## Todo Screen

أنشأنا شاشة خاصة بالمهام اللي لسا ما خلصت.

الشاشة تعرض فقط المهام اللي تكون:

isCompleted == false

وبالتالي المستخدم بقدر يشوف كل المهام المطلوبة بدون ما تختلط مع المهام المنتهية.
## Completed Screen

أنشأنا شاشة ثانية خاصة بالمهام المكتملة.

أي Task تكون:

isCompleted == true

بتظهر داخل هاي الشاشة.

وبالتالي صار في فصل واضح بين المهام المكتملة وغير المكتملة.

## كيف طبقت المفاهيم؟

بعد ما فصلنا الشاشات، أصبحت كل شاشة مسؤولة عن وظيفة محددة فقط.

بدل ما تعرض Home جميع المهام، صار كل Screen يعرض نوع معين من البيانات حسب حالة المهمة.

كمان استخدمت Widget مشتركة أكثر من مرة، وهذا خلاني أوفر كتابة كود مكرر، وإذا احتجت أعدل شكلها لاحقًا أعدله بمكان واحد فقط.

ومن خلال Bottom Navigation قدرت أربط كل الشاشات مع بعض بطريقة مرتبة، وصار التنقل بينها أسهل للمستخدم.

المشكلة الوحيدة كانت إني بالبداية لخبطت بين مسؤولية كل شاشة، لكن بعد تقسيم المشروع صار أوضح بالنسبة إلي وين لازم يكون كل جزء من الكود.

اليوم حسيت إني فهمت أكثر كيف يتم تنظيم مشاريع Flutter بطريقة صحيحة.

قبل كنت أركز إنه التطبيق يشتغل فقط، أما اليوم صار عندي فكرة إنه ترتيب الملفات وتقسيم المسؤوليات مهم بنفس أهمية كتابة الكود.

كمان فهمت ليش المطورين دائماً بحاولوا يقللوا تكرار الكود باستخدام Widgets مشتركة.

وصرت أعرف كيف أقسم التطبيق إلى أكثر من شاشة بدون ما يصير الكود معقد.

## أسئلة وإجابات
### 1. ليش استخدمنا Bottom Navigation Bar بدل التنقل من الأزرار داخل الصفحة؟

لأن Bottom Navigation مخصص للتنقل بين الصفحات الرئيسية داخل التطبيق، وهو أسهل للمستخدم لأنه موجود دائماً أسفل الشاشة. بالإضافة إلى ذلك، يعطي تجربة استخدام أفضل من الاعتماد على أزرار داخل كل صفحة.

### 2. ليش عملنا Widget مشتركة بدل نسخ نفس الكود؟

لأنه لو احتجنا نعدل تصميم المهمة مستقبلاً، بنعدلها مرة واحدة فقط داخل الـ Widget، وكل الشاشات رح تتحدث تلقائياً. وهذا يقلل الأخطاء ويخلي المشروع أسهل بالصيانة.

### 3. شو الفرق بين Todo Screen و Completed Screen إذا البيانات نفسها؟

البيانات محفوظة بنفس القائمة، لكن كل شاشة تعرض جزء مختلف منها.

Todo تعرض:

isCompleted == false

أما Completed تعرض:

isCompleted == true

يعني الاختلاف بطريقة العرض وليس بطريقة التخزين.

### 4. ليش ThemeData يعتبر مهم حتى بالمشاريع الصغيرة؟

لأنه من البداية بخلي تصميم التطبيق موحد. وإذا قررت أغير لون رئيسي أو إعداد معين، بغيره من مكان واحد بدل ما أبحث عنه داخل جميع الملفات.

### 5. شو فائدة تقسيم المشروع إلى Screens و Widgets؟

لأن كل ملف يصير مسؤول عن وظيفة محددة، وهذا يسهل قراءة الكود، ويخلي إضافة ميزات جديدة أو تعديل المشروع مستقبلاً أسهل بكثير.

### 6. ليش ما حطينا كل الكود داخل HomeScreen؟

لأن مع زيادة حجم المشروع رح يصير الملف طويل وصعب فهمه. تقسيم المشروع إلى ملفات مستقلة يخلي الكود أوضح، وأسهل لإيجاد الأخطاء وإعادة استخدام المكونات.

### 7. كيف التطبيق بعرف بأي شاشة يعرض المهمة؟

من خلال قيمة:

isCompleted

إذا كانت:

false

تظهر في Todo.

أما إذا كانت:

true

تظهر في Completed.

يعني نفس المهمة ممكن تنتقل بين الشاشتين بمجرد تغيير قيمتها.

### 8. ليش يعتبر تنظيم المشروع مهم حتى لو التطبيق صغير؟

لأن أي مشروع ممكن يكبر مع الوقت. إذا بدأنا بتنظيم الملفات من البداية، رح يكون أسهل نضيف شاشات أو Widgets جديدة بدون ما نضطر نعيد ترتيب المشروع كله.
